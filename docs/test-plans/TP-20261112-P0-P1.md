## 5. Resolved Questions & Remaining Risks

Sources: project README (`testsmith-io/practice-software-testing`), `docs/user-stories/v5.md`, and the Sprint 5 API scheduler (`sprint5/API/app/Console/Kernel.php`). All `[OBSERVED]` from source.

| Question | Answer | Plan Impact |
| :--- | :--- | :--- |
| Is sandbox data reset? | `[OBSERVED]` Yes. In `production` env the scheduler runs `migrate:fresh --seed` **hourly**, plus `invoice:remove` and `cache:clear` hourly. `invoice:generate` runs every minute and `order:update` every 10 min. | Tests must create their own data and never depend on data surviving more than ~1h. A reset can occur mid-run, so retry on 401 or missing data and prefer short, self-contained tests. Seeded accounts are always restored. |
| Admin credentials? | `[OBSERVED]` Public seeded accounts: `admin@practicesoftwaretesting.com` / `welcome01` (John Doe), `customer@practicesoftwaretesting.com` / `welcome01`, `customer2@...` / `welcome01`, `customer3@...` / `pass123`. | Public demo data, but still load via env vars (`ADMIN_EMAIL`, `ADMIN_PASSWORD`) to keep tests environment-agnostic. Changes to these accounts (e.g. password change in MOD-11) are reverted by the hourly reset, but should use throwaway users where possible. |
| Geo discounts deterministic? | `[OBSERVED]` Driven by **browser geo-location** (not IP). Fixed table: New York 5%, Mumbai 10%, Tokyo 15%, Amsterdam 20%, London 25%; other locations get none (AC3). | Deterministic: use Playwright `geolocation` + `permissions: ['geolocation']` context options per city (parametrized test). `[INFERRED]` matching is by proximity to city coordinates. Confirm radius/tolerance when specifying MOD-15. |
| PDF validation approach? | `[OBSERVED]` Invoices have a "Download PDF" button (AC6), a generation-status state (AC7: PDF still being generated) and a download (AC8). PDFs are generated asynchronously by `invoice:generate` every minute. | Poll with auto-retrying assertions (no sleeps) until the button is enabled, then validate the download: `%PDF-` magic bytes, content type and non-zero size. Parsing the text for invoice number/total is recommended as a deeper check `[TBD]` (needs a PDF parsing dependency). Hourly `invoice:remove` can delete PDFs, so generate the invoice in the same test. |
| CI platform? | `[TBD]` Not answered by the source. The upstream project uses GitHub Actions, which fits this repo's planned `.github/workflows/mate-qa.yml`. | Proceed with GitHub Actions unless you say otherwise. |
| TC filenames? | Local question, not answered by the site. | Confirm against `docs/test-cases/` per module. |

### Remaining Risks
* Hourly reset can invalidate sessions or data mid-run: design for idempotent, self-contained tests (see above).
* `DEC-OVR-01`: whitespace-only search accepted (provisional). Needs spec confirmation against `v5.md`.
* "Sprint 5 (with bugs)" hosted variant exists (`with-bugs.practicesoftwaretesting.com`). Do not mix it with this target. It could be a useful secondary target to validate that our suite detects defects.
